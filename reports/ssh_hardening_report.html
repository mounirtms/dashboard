Date: June 14, 2026
Performed by: Qoder Automated Security Team
Reviewed by: Mounir Abderrahmani
OS: AlmaLinux 8.10 (Cerulean Leopard) — OpenSSH

Executive Summary: A comprehensive SSH security audit revealed 2,043 brute-force login attempts in a single day from 42 unique IP addresses, with 53,269 total failed attempts recorded in server history. The SSH configuration had multiple critical weaknesses: root password login was permitted, MaxAuthTries was set to 10 (allowing extensive guessing), no fail2ban was installed to auto-ban attackers, and the /var/log/btmp file had world-writable permissions (777). All issues have been remediated: root password login disabled, fail2ban deployed (already banning attackers), auth limits tightened, and the lms user removed from the allowed SSH users list. The server is now protected against automated brute-force attacks.

2. Vulnerabilities Found

#VulnerabilitySeverityPrevious ValueRisk
1 Root password login enabled CRITICAL PermitRootLogin yes Attackers could brute-force root password directly. 448 root login attempts observed in one day.
2 Excessive MaxAuthTries HIGH MaxAuthTries 10 Each connection allowed 10 password guesses before disconnection, amplifying brute-force efficiency.
3 No fail2ban / auto-ban mechanism HIGH Not installed Attackers could retry indefinitely without being blocked. Top IP made 760 attempts without consequence.
4 Excessive MaxSessions MEDIUM MaxSessions 100 Allowed 100 concurrent sessions per connection, enabling resource exhaustion attacks.
5 No login grace time limit MEDIUM Default (120s) Unauthenticated connections held open for 2 minutes, wasting server resources.
6 SSH agent forwarding enabled MEDIUM AllowAgentForwarding yes Could allow SSH agent hijacking if a user session is compromised.
7 /var/log/btmp world-writable (777) MEDIUM rwxrwxrwx Failed login log could be tampered with by any user. SSH was warning on every connection.
8 Inactive user lms in AllowUsers LOW AllowUsers ... lms ... Unnecessary user in the SSH allow list expands the attack surface. No SSH keys configured.

3. Remediation Applied

All 8 vulnerabilities have been fixed. Changes took effect on June 14, 2026 at 14:10 CET.

3.1 SSH Configuration Changes

SettingBeforeAfterImpact
PermitRootLogin yes prohibit-password Root can only log in via SSH key. Password brute-force against root is now impossible.
MaxAuthTries 10 3 Each connection now allows only 3 attempts before disconnection, reducing brute-force efficiency by 70%.
MaxSessions 100 5 Prevents session multiplexing abuse. 5 is sufficient for legitimate admin work.
LoginGraceTime 120s (default) 30s Unauthenticated connections dropped after 30 seconds, freeing server resources faster.
AllowAgentForwarding yes no Prevents SSH agent hijacking attacks through compromised sessions.
AllowUsers technadminy7 lms dnd root salah tsdnd technadminy7 dnd root salah tsdnd Removed inactive lms user (no SSH keys configured), reducing attack surface.
