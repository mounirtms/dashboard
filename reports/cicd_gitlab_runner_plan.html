4. Issues Identified & Recommended Fixes

3 issues found — 1 configuration conflict, 1 security concern, 1 end-of-life dependency.

Issue 1: CONFLICT — concurrent vs limit

PropertyDetails
SeverityHigh
Problemconcurrent = 1 caps all jobs globally at 1, but limit = 3 allows this runner to accept 3 jobs. The 2 extra accepted jobs will be stuck waiting.
ImpactJobs queue up unnecessarily; misleading configuration
Fix Option AIf 1 job at a time is intended: set limit = 1
Fix Option BIf 3 parallel jobs are needed: set concurrent = 3

Issue 2: SECURITY — network_mode = "host"

PropertyDetails
SeverityMedium
ProblemHost network mode removes all network isolation between the CI container and the server. The container can access any service on the host.
ImpactIf CI jobs are compromised, attacker has full network access to the host
RecommendationUse network_mode = "bridge" (Docker default) unless host networking is specifically required by Magento build steps
ExceptionKeep host only if jobs need to reach services bound to localhost on the server. Document the reason.

Issue 3: EOL — image = "ruby:2.7"

PropertyDetails
SeverityMedium
ProblemRuby 2.7 reached End-of-Life in March 2023. No more security patches or bug fixes.
ImpactKnown vulnerabilities will remain unpatched; compliance risk
RecommendationUpgrade to ruby:3.2 or ruby:3.3 if Magento build supports it
VerificationTest the CI pipeline with the new image before switching in production

7. Step-by-Step Installation Guide

All commands below require root/sudo access. The server support team must execute these as root or with sudo. Estimated total time: 15–20 minutes.

Step 1: Install Docker CE

1 Add the Docker CE repository and install Docker Engine on AlmaLinux 8.10. 
# Remove any old/conflicting Docker packages
sudo yum remove -y docker docker-client docker-client-latest \
  docker-common docker-latest docker-latest-logrotate \
  docker-logrotate docker-engine podman runc 2>/dev/null

# Install required utilities
sudo yum install -y yum-utils

# Add the official Docker CE repository (works on AlmaLinux/RHEL 8)
sudo yum-config-manager --add-repo \
  https://download.docker.com/linux/centos/docker-ce.repo

# Install Docker CE, CLI, and containerd
sudo yum install -y docker-ce docker-ce-cli containerd.io \
  docker-buildx-plugin docker-compose-plugin

# Start Docker and enable it to start on boot
sudo systemctl start docker
sudo systemctl enable docker
1b Verify Docker is running correctly. 
# Check Docker version
docker --version

# Check Docker service status
sudo systemctl status docker

# Run the hello-world test container
sudo docker run hello-world
Expected output: docker --version should show Docker 27.x or later. systemctl status docker should show active (running). The hello-world container should print "Hello from Docker!"

Step 2: Install GitLab Runner

2 Add the GitLab Runner repository and install the package. 
# Add the official GitLab Runner repository
curl -L "https://packages.gitlab.com/install/repositories/runner/gitlab-runner/script.rpm.sh" | sudo bash

# Install GitLab Runner
sudo yum install -y gitlab-runner

# Verify installation
gitlab-runner --version
Expected output: gitlab-runner --version should show Version: 17.x.x or later with a git revision hash.

Step 3: Obtain the Registration Token from GitLab

3 Before registering, get the runner token from the GitLab web interface.
  • Log in to https://gitlab.com
  • Navigate to the target Project or Group
  • Go to Settings > CI/CD
  • Expand the Runners section
  • Click "New project runner" (or "New group runner")
  • Configure:
    • Check "Run untagged jobs" = OFF (we want tagged only)
    • Check "Lock to current project" = ON (recommended for prod)
    • Check "Maximum job timeout" = leave default or set 3600 (1 hour)
  • Click "Create runner"
  • Copy the registration token — you'll need it for the next step
Important: The token shown in GitLab is a one-time use token. Copy it before closing the page. The XXXXXXXXXXXXXXXXXXXXXXX in the commands below must be replaced with this actual token.

Step 4: Register the Runner

4 Register the runner with GitLab using the token obtained in Step 3. 
# Register the runner (non-interactive mode)
sudo gitlab-runner register \
  --non-interactive \
  --url "https://gitlab.com/" \
  --registration-token "REPLACE_WITH_ACTUAL_TOKEN" \
  --description "techno-magento-prod-runner" \
  --tag-list "techno-magento-prod-runner" \
  --executor "docker" \
  --docker-image "ruby:3.2" \
  --docker-privileged=false \
  --docker-network-mode="bridge" \
  --docker-volumes "/cache" \
  --limit 1 \
  --locked
Expected output: Runner registered successfully. Feel free to start it, but if it's already running simply restart it. The config file is created at /etc/gitlab-runner/config.toml.

Step 5: Verify & Fine-Tune config.toml

5 Review and adjust the generated configuration file. 
# View the generated configuration
sudo cat /etc/gitlab-runner/config.toml

# Edit if needed (e.g., to adjust network_mode or image)
sudo nano /etc/gitlab-runner/config.toml

Step 6: Start & Enable the Runner Service

6 Start the runner as a system service and configure it to start on boot. 
# Install the runner as a systemd service
sudo gitlab-runner install --user gitlab-runner --working-directory /home/gitlab-runner

# If the gitlab-runner user doesn't exist yet, create it:
sudo useradd -m -s /bin/bash gitlab-runner 2>/dev/null

# Install the service with the correct user
sudo gitlab-runner install --user gitlab-runner --working-directory /home/gitlab-runner

# Start the runner
sudo gitlab-runner start

# Verify it's running
sudo gitlab-runner status

# Enable auto-start on server boot
sudo systemctl enable gitlab-runner
Expected output: gitlab-runner status should show Runtime platform ... pid=XXXX running=true. The runner is now polling GitLab for jobs.

Step 7: Verify Runner in GitLab UI

7 Confirm the runner appears online in the GitLab dashboard.
  • Go to the GitLab project/group
  • Navigate to Settings > CI/CD > Runners
  • Confirm techno-magento-prod-runner appears with:
    • Status: ONLINE
    • Tag: techno-magento-prod-runner
    • IP Address: matches the server IP
    • Version: matches the installed GitLab Runner version

8. Testing & Validation

Test 1: Docker Health Check

Confirm Docker can pull images and run containers on this server. 
# Pull the Ruby 3.2 image (the default CI image)
sudo docker pull ruby:3.2

# Run a quick test
sudo docker run --rm ruby:3.2 ruby -e "puts 'Ruby ' + RUBY_VERSION + ' is working'"
Expected: Ruby 3.2.x is working — confirms Docker can pull images from Docker Hub and execute containers.

Test 2: Runner Configuration Validation

Verify the runner config is syntactically correct and the runner can reach GitLab. 
# Verify configuration
sudo gitlab-runner verify

# List registered runners
sudo gitlab-runner list
Expected: Both commands complete without errors. list shows techno-magento-prod-runner with the correct URL and token.

Test 3: Debug Mode (Live Job Polling)

Run the runner in debug mode to see real-time job polling logs. Useful for troubleshooting. 
# Stop the service first (debug mode runs in foreground)
sudo gitlab-runner stop

# Run in debug mode (Ctrl+C to stop)
sudo gitlab-runner --debug run

# Watch for: "Checking for jobs..." and "Feeding runner..." messages
# After confirming it works, stop with Ctrl+C and restart the service:
sudo gitlab-runner start
Expected: Logs show Checking for jobs... every few seconds. When a job is picked up, you'll see Feeding to runner... followed by Docker image pull and job execution logs.

Test 4: End-to-End CI/CD Job Test

Create a test pipeline in a GitLab project to confirm the runner picks up and executes jobs correctly. 
# Add this .gitlab-ci.yml to any project that has access to this runner:

test_runner:
  tags:
    - techno-magento-prod-runner
  script:
    - echo "Runner is working!"
    - ruby --version
    - uname -a
    - echo "Test completed at $(date)"
Expected: The job appears in CI/CD > Pipelines, is picked up by techno-magento-prod-runner, and passes with output showing the Ruby version and system info.

Test 5: Docker Network Mode Validation

Verify that the Docker network mode (bridge) works correctly for CI jobs. 
# Add this to .gitlab-ci.yml to test network connectivity:

test_network:
  tags:
    - techno-magento-prod-runner
  script:
    - echo "Testing network connectivity..."
    - curl -s --max-time 5 https://gitlab.com -o /dev/null && echo "GitLab reachable" || echo "GitLab unreachable"
    - curl -s --max-time 5 https://rubygems.org -o /dev/null && echo "RubyGems reachable" || echo "RubyGems unreachable"
    - hostname
    - ip addr show
Expected: Both GitLab reachable and RubyGems reachable confirm the container has outbound internet access in bridge mode. If either fails, switch to network_mode = "host" in config.toml.

Test 6: Cache Volume Validation

Confirm the /cache volume persists data between CI jobs. 
# Add this to .gitlab-ci.yml:

test_cache:
  tags:
    - techno-magento-prod-runner
  script:
    - mkdir -p /cache/test
    - echo "cache-$(date +%s)" > /cache/test/timestamp.txt
    - cat /cache/test/timestamp.txt
    - echo "Cache volume is mounted and writable"
Expected: The job writes a timestamp to /cache/test/timestamp.txt and reads it back successfully. On a subsequent run, the previous timestamp should still be present (cache persistence).

9. Troubleshooting Common Issues

ProblemDiagnosisFix
Runner shows offline in GitLab sudo gitlab-runner status — check if service is running sudo gitlab-runner restart — or check /var/log/syslog for errors
Permission denied on Docker socket ls -la /var/run/docker.sock Add gitlab-runner user to docker group: sudo usermod -aG docker gitlab-runner then restart the service
Jobs stuck in pending Check runner tags match the job tags in .gitlab-ci.yml Ensure job uses tags: [techno-magento-prod-runner]; verify runner is not locked to a different project
Docker pull timeout/failure sudo docker pull ruby:3.2 — test manually Check server internet connectivity; configure Docker proxy if behind firewall; try network_mode = "host"
Registration token rejected Token may be expired or already used Generate a new token from GitLab Settings > CI/CD > Runners > New runner
Runner picks up job but fails immediately Check debug logs: sudo gitlab-runner --debug run Usually a Docker image issue — verify the image exists and can be pulled; check disk space
